# 代理测试规范：godot-shader-specialist

## 代理摘要
领域：Godot 着色语言（GLSL 衍生语言）、可视化着色器（VisualShader 图）、材质设置、粒子着色器和后处理效果。
不负责：玩法代码、美术风格指导。
模型层级：Sonnet（默认）。
未分配门禁 ID。

## 测试用例

### 用例 1：领域内请求，输出适当
**输入：**“为 Godot 中的敌人死亡效果编写一个溶解着色器。”
**预期行为：**
- 生成有效的 Godot 着色语言代码（不是 HLSL，也不是直接使用 GLSL）
- 视情况使用 `shader_type spatial;` 或 `canvas_item`
- 定义 `uniform float dissolve_amount : hint_range(0.0, 1.0);`
- 对噪声纹理采样，以确定每个像素的溶解阈值
- 对低于阈值的像素使用 `discard;`
- 可选择在溶解边界附近使用自发光添加边缘辉光
- 代码在 Godot 着色语言中语法正确

### 用例 2：HLSL 重定向
**输入：**“为此溶解效果编写一个 HLSL 计算着色器。”
**预期行为：**
- 不生成 HLSL 代码
- 明确说明：“Godot 不直接使用 HLSL，而是使用自己的着色语言（一种 GLSL 衍生语言）”
- 将 HLSL 意图转换为等效的 Godot 着色器方案
- 说明 Godot 4 提供 RenderingDevice 计算着色器，但它属于底层 API；如果用户想要的是这种方案，应作出适当标记

### 用例 3：知识截止日期后的 API 变更，纹理采样（Godot 4.4）
**输入：**“在着色器中使用带 sampler2D 的 `texture()` 对噪声纹理采样。”
**预期行为：**
- 检查版本参考：Godot 4.4 更改了纹理采样器类型声明
- 标记潜在的 API 变更：`sampler2D` 语法和 `texture()` 调用行为可能与 4.4 之前不同
- 根据迁移说明，为项目锁定的版本（4.6）提供正确语法
- 不在未标记版本风险的情况下使用 4.4 之前的纹理采样语法

### 用例 4：片段着色器 LOD 策略
**输入：**“水面片段着色器进行了 8 次纹理采样，在中端硬件上造成了 GPU 瓶颈。”
**预期行为：**
- 识别出每个片段的纹理采样次数是主要成本来源
- 提出 LOD 策略：
  - 远距离时减少采样次数（使用基于距离的着色器变体或 LOD 级别）
  - 离线预烘焙部分纹理组合
  - 对远距离采样使用分辨率较低的噪声纹理
- 提供实现该 LOD 方案的着色器代码修改
- 不改变水体系统的玩法行为

### 用例 5：上下文传递，Godot 4.6 辉光重做
**输入：**引擎版本上下文：Godot 4.6。请求：“为场景添加泛光/辉光后处理效果。”
**预期行为：**
- 引用 VERSION.md 说明：Godot 4.6 包含辉光重做
- 使用 4.6 的 WorldEnvironment 方案给出辉光配置指导，而不是使用 4.6 之前的 API
- 明确说明 4.6 辉光重做中发生变化的属性或参数
- 标记因功能晚于知识截止日期而可能在 LLM 训练数据中存在错误信息的所有属性
